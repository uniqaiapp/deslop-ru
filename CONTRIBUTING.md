# Contributing to deslop-ru

Thanks for helping. The most useful contribution is a sentence: one the checker missed, or one it flagged for no reason. Open an issue with the sentence and, if you have one, the regex that would fix it.

## Local checks

```bash
python3 tests/run.py
```

Python 3.9+ standard library only; no packages, no network, under ten seconds. CI runs the same command on Python 3.9 and 3.12 and checks that the repo stays under 3 MB.

## Adding or changing a pattern

1. Edit the `_P` table in `scripts/deslop.py`. Each row is `(id, lang, category, regex, label, fix, weight, cut)`:
   - `id` is `<lang>.<category>.<slug>`; the tests check it matches `lang` and `category`.
   - Regexes run on a lowercased copy with `ё` folded to `е`, so write `е` only. Use stems with explicit endings, not `[а-я]*`, so the rule stays readable.
   - `weight`: 1 for a word that is sometimes fine (`эффективный`), 2 for a typical tell, 3 for a phrase that only a model writes (`давайте разберёмся`).
   - `cut: True` only if deleting the match never changes meaning. The regex must then swallow its own trailing comma and spaces (`[ \t]*`, never `\s*`, so paragraph breaks survive).
2. Add a positive sample to `POSITIVE` in `tests/test_checker.py` and, if the rule is at all ambiguous, a clean sentence to `NEGATIVE`.
3. Run `python3 scripts/regen_examples.py`. It rewrites `examples/reports/` and `references/patterns.md`. Read the diff: a new rule that changes an example score is fine, a new rule that fires on an `*.after.md` file is a false positive.
4. If the pattern count changed, update the numbers in `README.md`, `README.ru.md` and `SKILL.md` (the tests tell you which).
5. `python3 tests/run.py`.

## Adding an example

Two files, `examples/<name>.before.md` and `examples/<name>.after.md`, plus a row in `examples/README.md`. The "after" text must be a rewrite you would publish, not a minimal edit: same facts, your voice, shorter. Then `python3 scripts/regen_examples.py` and commit the generated reports.

## Pull requests

- Conventional Commits: `feat:`, `fix:`, `docs:`, `test:`, `chore:`.
- One rule or one example per PR where possible.
- The PR template asks for a before/after sentence and whether any new number in the docs comes from the script. Both are required.
- No personal names, screenshots of real user content, or secrets. Author of record for this repo is UniqAI <support@uniqai.app>.

## Assets

`assets/banner*.svg`, `assets/demo.svg` and `assets/social-preview.png` are generated by the uniqaiapp design kit (shared across the org, not part of this repo) from `assets/demo.txt`. `demo.txt` must be a real transcript: every output line in it has to appear in `examples/reports/` or in the checker's output on an example file, and `tests/test_examples.py` checks that. To change the demo, edit `demo.txt` and ask a maintainer to re-render, or open a PR with just the text change.

## Deviations from org conventions

- `.gitignore` omits the Node entries: the repo has no Node code, and the forbidden-strings test would flag the directory name.
- The README follows the newer design-kit template (banner `<picture>`, badge row, feature grid) rather than the older section list in the conventions document; the sections required there (usage, limits, related) are present under the template's headings.
